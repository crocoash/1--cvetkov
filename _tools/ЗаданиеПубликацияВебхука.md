# Задание: опубликовать HTTP-сервис ТелеграмВебхук и включить вебхук

Это задание для Claude Code, запущенного **на машине с 1С и веб-сервером**. Здесь, на машине
разработки, ни базы, ни Конфигуратора, ни веб-сервера нет — поэтому всё, что ниже, проверить
отсюда невозможно, и написано оно по коду, а не по наблюдению.

Цель: нажатия кнопок под сообщениями менеджеру в Telegram должны приходить в 1С **мгновенно**,
через вебхук, а не опросом раз в минуту.

## Что уже сделано (трогать не нужно)

* В конфигурации есть `HTTPСервис.ТелеграмВебхук` — `Корневой URL = tg`, шаблон `/hook`,
  метод `Принять` (POST). Модуль: `HTTPServices/ТелеграмВебхук/Ext/Module.bsl`.
* Есть роль `ТелеграмВебхукДоступ` с единственным правом — вызвать этот сервис. Больше ей ничего
  не нужно: код внутри первым делом включает привилегированный режим.
* В `CommonModules/ТелеграмБот/Ext/Module.bsl` есть функция `СекретВебхука()` — сейчас возвращает
  пустую строку. **Пустой секрет = сервис отвечает 403 на всё**, вебхук выключен, нажатия
  забирает регламент `ТелеграмОбмен` опросом `getUpdates`.
* Токен бота — в функции `ТокенБота()` того же модуля. Бот `@cvetkov_manager_bot`.

## Порядок

### 0. Убедиться, что конфигурация в базе свежая

```
git pull
```

Затем в Конфигураторе — «Загрузить конфигурацию из файлов» и обновление конфигурации БД.
`HTTPСервис.ТелеграмВебхук` и роль `ТелеграмВебхукДоступ` — новые объекты метаданных, поэтому
нужно принять структурные изменения, одного F7 без подтверждения мало.

### 1. Веб-сервер с CGI

PowerShell от администратора. Сначала определить тип ОС:

```powershell
(Get-CimInstance Win32_OperatingSystem).Caption
(Get-CimInstance Win32_OperatingSystem).ProductType   # 1 = клиентская, 2/3 = серверная
```

Серверная:

```powershell
Install-WindowsFeature -Name Web-Server,Web-CGI,Web-Mgmt-Console -IncludeManagementTools
```

Клиентская:

```powershell
Enable-WindowsOptionalFeature -Online -All -FeatureName `
  IIS-WebServerRole,IIS-WebServer,IIS-CommonHttpFeatures,IIS-CGI,IIS-ManagementConsole
```

`CGI` обязателен — без него модули 1С не работают.

Проверка:

```powershell
Get-Service W3SVC
Invoke-WebRequest http://localhost -UseBasicParsing | Select-Object StatusCode
```

**Перед этим шагом стоит выяснить, не опубликованы ли веб-сервисы МИКО (телефония,
`1C_MIKO_identify_number.1cws`) на ДРУГОЙ машине.** Если да — всю публикацию проще делать там:
веб-сервер и модули 1С уже настроены, останется одна галка.

### 2. Модули расширения веб-сервера 1С

Запустить `setup.exe` дистрибутива **той же версии, что установлена** → «Изменить» →
отметить «Модули расширения веб-сервера».

Версию посмотреть так:

```powershell
Get-ChildItem "C:\Program Files\1cv8" -Directory | Select-Object Name
```

Ожидается 8.3.25.1374 (версия из `Configuration.xml`).

Тихую установку через `msiexec ADDLOCAL=` **не использовать**: при неполном списке компонентов
она снесёт уже установленные, включая Конфигуратор.

Конфигуратор после установки перезапустить **от имени администратора** — иначе он не сможет
писать конфиг веб-сервера.

### 3. Пользователь 1С

Создать пользователя `ТелеграмВебхук`:

* аутентификация 1С:Предприятия — включить, задать длинный пароль (понадобится в `default.vrd`);
* аутентификация ОС и OpenID — снять;
* «Показывать в списке выбора» — снять;
* «Защита от опасных действий» — оставить;
* роль — **только** `ТелеграмВебхукДоступ`, никаких других.

Существующий пользователь «Служебный» не подходит: у него пустой пароль, а публикация будет
доступна из интернета.

### 4. Публикация

Конфигуратор → Администрирование → Публикация на веб-сервере. Отдельной публикацией
(алиас, например `tgbot`), а не поверх публикации МИКО.

* вкладка «HTTP-сервисы» — отметить `ТелеграмВебхук`;
* в `default.vrd` в строке соединения прописать `Usr=ТелеграмВебхук;Pwd=<пароль>`.

Про `Usr`/`Pwd` забыть нельзя: Telegram не умеет проходить аутентификацию 1С и получит 401.

Адрес получится такой:

```
https://<хост>/tgbot/hs/tg/hook
```

`hs` — фиксированный префикс HTTP-сервисов, `tg` — корневой URL сервиса, `/hook` — шаблон.

### 5. Проверка доступности — до всякого Telegram

С машины **вне локальной сети**:

```
curl -i -X POST https://<хост>/tgbot/hs/tg/hook -d "{}"
```

Правильный ответ на этом этапе — **403**. Он означает: сертификат принят, веб-сервер отдал
запрос в 1С, сервис отработал и отклонил его из-за пустого секрета. Это и есть критерий,
что публикация удалась.

Расшифровка других ответов:

| ответ | причина |
|---|---|
| 401 | не прописаны `Usr`/`Pwd` в `default.vrd` |
| 404 | сервис не отмечен в публикации, либо неверный алиас/путь |
| 500 | сервис вызвался, но упал — смотреть журнал регистрации, событие `Телеграм.Вебхук` |
| таймаут | база не видна из интернета: проброс порта, firewall, DNS |

Telegram принимает вебхук только на портах **443, 80, 88, 8443** и требует валидный сертификат
(самоподписанный тоже можно, но его нужно загружать в `setWebhook` — проще нормальный).

### 6. Секрет и включение

Придумать секрет: латиница, цифры, `_`, `-`, до 256 символов.

Вписать его в `СекретВебхука()` в `CommonModules/ТелеграмБот/Ext/Module.bsl` (сейчас там
`Возврат "";`), затем:

```
pwsh -NoProfile -File _tools/snapshot.ps1 "Telegram: включён вебхук"
```

Скрипт сам прогонит fix→check штрихкодов, закоммитит и запушит. Перед правкой — `git pull`,
на машине разработки файл могли поменять.

Загрузить конфигурацию из файлов, обновить конфигурацию БД. **Сразу после этого** вызвать
setWebhook (токен взять из `ТокенБота()`):

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook
   ?url=https://<хост>/tgbot/hs/tg/hook
   &secret_token=<СЕКРЕТ>
   &allowed_updates=["callback_query","message"]
   &drop_pending_updates=true
```

`drop_pending_updates=true` выбросит накопившиеся необработанные нажатия — иначе они прилетят пачкой.

**Почему «сразу»:** заполненный секрет отключает опрос `getUpdates` (см. `ОбменСБотом`).
Между загрузкой конфигурации и вызовом setWebhook кнопки не работают вообще: опроса уже нет,
вебхука ещё нет. Делать эти два шага подряд, а не «секрет сегодня, setWebhook завтра».

### 7. Приёмка

В консоли кода на сервере:

```
Сообщить(ТелеграмБот.Диагностика());
```

Ожидается:

* `Вебхук: https://<хост>/tgbot/hs/tg/hook`
* `Нажатия кнопок: приносит вебхук (HTTPСервис.ТелеграмВебхук), опрос отключён`
* `Ждёт обновлений: 0`

Затем нажать в чате кнопку «🔄 <статус>» под любым сообщением: сообщение должно перерисоваться
**мгновенно**, всплывашка со сводкой — появиться сразу, а не через минуту.

В журнале регистрации на каждое нажатие должна появляться запись `Телеграм.Кнопка`.

## Чего НЕ делать

* Не трогать публикацию веб-сервисов МИКО — на ней работает телефония.
* Не давать пользователю `ТелеграмВебхук` никаких ролей, кроме `ТелеграмВебхукДоступ`,
  и тем более не «Полные права»: публикация смотрит в интернет.
* Не выключать и не удалять регламент `ТелеграмОбмен`. Вебхук закрывает только входящие
  нажатия. Очередь уведомлений о смене статуса и досылку отложенных с ночи уведомлений
  о новых заказах развозит он же — расписание раз в 1–2 минуты нужно при любом раскладе.
* Не включать вебхук, пока шаг 5 не дал 403 снаружи.

## Откат

Если что-то пошло не так:

1. `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`
2. вернуть в `СекретВебхука()` пустую строку, снимок, загрузить конфигурацию.

1С сразу вернётся к опросу регламентом — то есть к тому, как всё работает сейчас.
