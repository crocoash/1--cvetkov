Документ "Реєстрація авансів в податковому обліку"

Документ "Реєстрація авансів у податковому обліку" призначений для коректування очікуваного податкового кредиту й податкових зобов'язань по всіх незакритих авансах, для договорів яких встановлений метод «по оплаті» або «по першій події» по обліку ПДВ або податку на прибуток, а також закриття "неповних" повернень (див. нижче).

Документ вводиться наприкінці податкового періоду, після реєстрації всіх первинних  (відвантажувальних, податкових) документів. На початку наступного податкового періоду прийняті коректування будуть компенсовані з метою збереження принципу роботи "по відвантаженню" протягом податкового періоду

Після автоматичного заповнення користувачеві необхідно визначити параметри податкового обліку для кожного "авансу", що буде зареєстрований.

Для видів операцій "Аванс: визначення параметрів ПО", "Аванс (повернення): визначення параметрів ПО" необхідно вибрати ставку ПДВ, податкове призначення, по яких аванс повинен бути зареєстрований. Ці види операцій можуть бути позначені в договорах для моменту визначення податкової бази «по оплаті», або «по першій події», у випадку якщо оплат зареєстровано більше чим відвантажень

Для видів операцій "Відвантаження: скасування реєстрації в ПО", "Відвантаження (повернення): скасування реєстрації в ПО" необхідно вибрати ставку ПДВ, по яких потрібно скасувати реєстрацію очікуваного ПДВ на суму відвантажень, що перевищують оплату. Ці види операцій можуть бути вікористані тільки для договорів з моментом визначення податкової бази «по оплаті», у випадку якщо відвантажень зареєстровано більше чим оплат

Залежно від того, які методи визначення податкової бази обрані для конкретного договору, у рядку проставляються ознаки "ПДВ" ("Реєстрація з обліку ПДВ") і "ПНП" ("Реєстрація з обліку податку на прибуток"). По цих ознаках можна визначити, чи буде виконуватися коригування (визначення параметрів для авансу або скасування реєстрації відвантаження) по конкретному рядку. Ознаки "ПДВ" і "ПНП" визначаються автоматично при заповненні по залишкам чи при виборі договору

При проведенні документа, по табличній частині "Придбання":

- формуються коригувальні рухи по регістрах "Очікуваний і підтверджений ПДВ Придбань", "Придбання податковий облік";

- бухгалтерські проводки за планом рахунків бухгалтерського обліку між рахунком податкового кредиту (вибирається в реквізиті "Рахунок ПДВ") і рахунком непідтвердженого податкового кредиту (вибирається в реквізиті "Рахунок непідтвердженого ПДВ"), на суму коригування очікуваного податкового кредиту;

- бухгалтерські проведення по податковому плану рахунків по рахунку ВР на суму коригування валових витрат;

По табличній частині "Продажу":

- формуються коригувальні рухи по  регістрах "Очікуваний і підтверджений ПДВ Продажів", "Продажі податковий облік";

- бухгалтерські проводки за планом рахунків бухгалтерського обліку між рахунком обліку непідтверджених податкових зобов'язань (вибирається в реквізиті "Рахунок непідтвердженого ПДВ") і рахунком  податкових  зобов'язань (вибирається в реквізиті "Рахунок ПДВ"), на суму коригування очікуваних податкових зобов'язань;

- бухгалтерські проводки по податковому плану рахунків по рахунку ВД на суму коригування валових доходів;

 

Для всіх рухів на момент початку наступного податкового періоду (місяця) прийняті коригування сторнуються (формуються "зворотні" рухи й проводки) з метою збереження принципу роботи "по відвантаженню" для наступного податкового періоду

 

Ще однієї функцією документа є закриття в податкових регістрах "неповних" операцій повернення. Наприклад: покупець повернув відвантажений йому товар, причому ні оплати ні повернення оплати не було.

Для цієї операції призначена закладка "Повернення".

Після автоматичного заповнення даних на закладці користувач може відкоригувати суми в колонці "Сума повернутого відвантаження (оплати)" (позитивна сума означає повернуте відвантаження, від'ємна - оплату).

Якщо встановлено прапорець "Не передбачається закриваюча операція" - при проведенні будуть сформовані проведення по регістру "Продажі податковий облік" або "Придбання податковий облік" (залежно від типу контрагента) в припущенні, що, наприклад, по повернутих товарах не передбачається взаємного перерахування грошей (повернення оплати) .

 

Для формування коректних проведень при закритті неповних повернень важливо, щоб і реєстрація авансів і закриття повернень (щодо одного і того самого договора) відбувалося одним документом.

 

ЗАУВАЖЕННЯ: При проведенні документ "закриває" регістри "Продажі податковий облік" і "Придбання податковий облік", тобто, списує з регістра дані по взаєморозрахунках з контрагентами, що відносяться до закритих ("повних") операцій, тобто по тим операціям, по яких відбулися як відвантаження так і оплата (або взаємні відвантаження в випадку бартерного договору).
